# Frontier scaling roadmap

| Stage | Model/program | Evidence earned before entry | Exit evidence |
|---|---|---|---|
| S0 | 100M | G0 laboratory | G1 repeatable communication/quality result |
| S1 | 500M–1B | finalist algorithms | independent two-island reproduction |
| S2 | 3–7B | real WAN and heterogeneous schedule | G3 multi-operator reliability/economics |
| S3 | 20–40B / Track A RL | safe rollout/verifier plane | measured capability gain and fraud resistance |
| S4 | 100B+ sparse | local MoE/router and state-lifecycle evidence | G5 hierarchical scaling result |
| S5 | frontier attempt | independent G6 review, governance/security/funding | public reproducible evidence, not parameter count |

## Operational frontier definition

A model is frontier-relative when, at a dated evaluation, it falls within a declared leading capability band across a balanced portfolio of agentic completion, coding, mathematics/science, multimodality, tool use, long context, and inference-time scaling, subject to contamination and safety review. Parameter count and training FLOPs are inputs, not the definition.

Track A starts from the strongest appropriately licensed open-weight model selected at execution time and uses federation for data, trajectories, evaluation, SFT/RL, specialization, and merging. Track B trains the full research model through the stages above. Track A creates useful systems sooner; it does not prove federated pretraining.

Every stage estimates training, post-training, evaluation, and inference-time compute separately. Sparse models report total and active parameters. A 100B run is prohibited from compensating for a failed 1B mechanism by scale alone.
